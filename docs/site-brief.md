# PW 网站需求与第一阶段边界

依据：已读取仓库 README.md，并合并创建者于 2026-10-05 提出的需求。PW 仅是项目代号，正式名称、头像、个人资料和真实内容待创建者提供。

## 定位与内容结构

这是个人兴趣、思维与生活记录网站，暂不包含办公功能、职业作品集或工作项目。

| 公开栏目 | 内容 |
| --- | --- |
| 交通与地图 | 铁路、航空、城市交通、线路历史、交通地理、地图 |
| NIMBY Rails | 自建网络、线路构想、运行方案、规划记录 |
| 旅行与散步 | 照片、路线、城市观察；区分实际记录、计划、资料研究 |
| 语言与文化 | 英语、日语、法语学习、地名、影视表达、跨文化观察 |
| 音乐 | 听后感、歌单、音乐生活；夜鹿专题包含听后感、衍生小说、圣地巡礼 |
| 日常随笔 | 生活短记、自我观察、思考与长文 |
| 关于我 | 创建者确认后填写个人介绍、兴趣、建站初衷 |

长文章与短记共用内容模型：标题、类型、栏目、摘要、正文、日期、标签、公开状态、草稿/发布状态；照片包含说明与替代文本。专题独立聚合，夜鹿细分听后感、衍生小说、巡礼资料/计划/实际记录。不得把示例叙述当作创建者真实经历，不提供未经授权的歌词、音频或专辑封面。

## 私密空间：记忆阁楼

仅创建者本人访问，保存往事、日记、照片；按日期、事件、地点、人物组织，提供人物索引、时间线、原始记录与带日期的回看笔记、备份和导出。

后续实现必须使用真实身份验证与服务端权限检查。日记正文、照片原图、缩略图、附件与下载接口均受保护；隐藏地址、前端检查、静态 JSON、打包进 JavaScript 或公开对象存储均不构成权限保护。真实私密内容、密钥和备份不得提交到 Git，不得进入公开页面、搜索、更新列表、站点地图、构建资源或 PWA 缓存。发布要由创建者明确选择，私密内容默认为私密。

## 内容管理与长期技术方向

管理界面应支持新建/编辑长文、保存草稿、发布短记、照片上传和说明、栏目与标签管理、明确选择公开或私密。手机优先兼顾桌面，之后实现离线草稿与同步，评估 Capacitor 安卓 App；网页与 App 共用账号、内容与权限系统。

第一阶段采用无依赖 HTML/CSS/JavaScript 原型和 Node 本地静态预览服务，方便维护与预览，不提前锁定后台供应商。下一阶段建议独立服务端内容 API、关系数据库、私有对象存储和仅允许创建者账户的身份认证。最终框架、认证服务、数据库、存储供应商及部署成本须结合实际托管环境确定。公开内容由发布状态过滤；私密数据使用独立授权路径，不能依赖客户端过滤。

## 第一阶段交付与验收

- 可运行的响应式首页、七个公开栏目、文章详情、短记、夜鹿专题。
- 文章阅读字号切换、照片呈现位置、原创示意地图与插画，所有内容明确标注示例。
- 私密入口明确说明尚未实现身份验证，只能进入公开的虚构展示；日期、事件、人物筛选及时间线使用虚构记录。
- 管理界面为内存演示：草稿、公开模拟发布、图片本地预览，刷新即清除，不向服务器上传，不接收真实私密资料。
- PWA 安装基础（manifest、图标、公开静态壳离线缓存）；不缓存私密内容或编辑状态。安装支持取决于浏览器，原型不是已完成的离线编辑系统。
- 本地预览命令、说明、自动化检查、GitHub 同步。

第一阶段不包含真实后台、登录、永久保存、真实发布、私密文件上传或生产部署。公开静态演示中的“记忆阁楼”内容是虚构的，绝不能被当作安全空间。

## 后续验收重点

1. 内容管理：保存后重开仍存在、草稿不可公开访问、发布/撤回状态一致、照片验证与说明。
2. 权限：未登录与其他账户不能读取私密记录、附件和缩略图；枚举 ID、直接访问 API、失效会话均拒绝；公开构建、日志和缓存无私密内容。
3. 手机、备份和部署：安卓操作、照片上传、导出恢复、HTTPS、私密缓存策略和会话退出清理。
